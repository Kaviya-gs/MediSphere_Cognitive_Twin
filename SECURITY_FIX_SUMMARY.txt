ISSUE
================================================================================

Frontend calls to backend were returning HTTP 403 Forbidden:
  GET http://localhost:8080/api/v1/patients/list/active → 403 Forbidden
  GET http://localhost:8080/api/v1/health/status → 403 Forbidden
  GET http://localhost:8080/api/v1/vitals/... → 403 Forbidden
  And all other /api/v1/** endpoints

ROOT CAUSE
================================================================================

SecurityConfig.java had:
  .requestMatchers("/v1/**").permitAll()

But actual request paths are:
  /api/v1/patients (due to servlet context-path: /api in application.yml)

The path pattern /v1/** does NOT match /api/v1/**, causing all requests
to be blocked by Spring Security.

SOLUTION
================================================================================

File: backend/src/main/java/com/medisphere/config/SecurityConfig.java

Changes:
1. Fixed path matchers:
   - .requestMatchers("/api/v1/**").permitAll()  ← Matches /api/v1/**
   - .requestMatchers("/v1/**").permitAll()      ← Fallback for requests without context path

2. Added CORS configuration:
   - Allowed origins: localhost:4200, localhost:52204, 127.0.0.1:4200/52204
   - Allowed headers: X-User-Role, X-User-Patient-Id, Authorization, etc.
   - Exposed headers for cross-origin browser access
   - Methods: GET, POST, PUT, DELETE, PATCH, OPTIONS

3. Enabled custom header-based authorization:
   - X-User-Role: Identifies role (ADMIN or PATIENT)
   - X-User-Patient-Id: Identifies patient (for PATIENT role)
   - Controllers enforce authorization based on these headers
